# Чек-лист цифрового решения — Агент сотрудника службы безопасности

<!-- → сущность ope_checklists. -->

- [ ] Паспорт агента (`agent.yaml`) утверждён, зарегистрирован в реестре (agents, agent_versions).
- [ ] Контракты `input/output` соответствуют образцу платформы (п. 4.8); результаты валидны (T1).
- [ ] Каждый фактор риска содержит `source_reference` (документ/реестр, дата обращения, статус) (T3).
- [ ] Правила уверенности понижают `data_confidence` и ставят `requires_human_review` (T4).
- [ ] Точки HITL не обходятся; фиксация вердикта в 1С только после `human_approve` (T5, write_gate).
- [ ] Вызовы только из `tools.yaml`, зафиксированы в `tool_calls` (T6).
- [ ] Чтение/запись 1С — через OData/HTTP-сервис по белому списку; внешние реестры — только
      через `ext.check_official_registries` (T7).
- [ ] Отказ одного источника не роняет граф — частичный результат (T8).
- [ ] Каждое действие имеет `correlation_id` и нормативное основание (T9).
- [ ] Параллельный запуск не теряет кейсы (T10).
- [ ] Заключение не выдаётся при неоднозначной идентификации или покрытии критериев < 100% (K1, K6).
- [ ] Персональные данные обрабатываются в объёме проверки; маскирование ПДн на уровне LLM Gateway.
- [ ] Доля необоснованных блокировок безопасных контрагентов ≤ 5% (guardrail-KPI K3).
- [ ] Приёмочное тестирование с владельцем процесса и пилотной группой (T11).
