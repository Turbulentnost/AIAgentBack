# Программа ОПЭ — Агент сотрудника службы безопасности

<!-- → сущность ope_reports (программа). -->

## Цель
Подтвердить промышленную пригодность агента на реальных кейсах проверки контрагента при
сохранении управленческой вертикали и ответственности человека.

## Объём и длительность
- Длительность и объём выборки кейсов определяются владельцем процесса.
- Покрытие всех task_type: new_supplier_check, periodic_recheck, contract_check, exception_check.

## Сценарии проверки
1. Новый поставщик с полными реквизитами → полная проверка и заключение.
2. Неоднозначная идентификация (нет ИНН / несколько карточек / расхождение) → возврат
   закупщику с запросом реквизитов; проверка не выполняется.
3. Покрытие обязательных критериев < 100% → перечень недостающих сведений; заключение не выдаётся.
4. Средний риск → проект «УСЛОВИЯ ДОПУСКА»; высокий риск → «ОТКАЗ» + утверждение руководителя СБ.
5. Расхождение данных 1С и официального реестра → понижение уверенности, передача человеку.
6. Проверка запрета записи вердикта без прохождения узла human_approve (write_gate).
7. Отказоустойчивость: недоступность одного источника → частичный результат с понижением уверенности.
8. Исключение до 10 000 руб. (контур №4) → совместное согласование финансового директора и СБ.

## Критерии успеха
Достигнуты блокирующие KPI (`kpi.yaml`), пройдены проверки T1–T11 (`tests/`),
замечания журнала закрыты или переведены в план доработки с согласия владельца процесса.
