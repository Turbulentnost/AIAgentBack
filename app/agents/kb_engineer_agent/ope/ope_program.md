# Программа ОПЭ — Агент инженера КБ / ГСПП

<!-- → сущность ope_reports (программа). -->

## Цель
Подтвердить промышленную пригодность агента на реальных кейсах технической проверки аналога/
замены/отклонения при сохранении управленческой вертикали и ответственности человека.

## Объём и длительность
- Длительность и объём выборки кейсов определяются владельцем процесса.
- Покрытие всех task_type: analog_review, substitution_review, kd_deviation_review,
  spec_clarification.

## Сценарии проверки
1. КД актуальна → извлечение обязательных требований и разбор аналога.
2. КД неактуальна/не найдена → заключение не выдаётся, запрос актуальной КД (low + review).
3. Аналог с неполными обязательными данными → перечень недостающих данных закупщику.
4. Покрытие критериев 100%, несовпадение диапазона → «РАЗРЕШЕНИЕ» с условиями и изменением КД.
5. Покрытие < 100% или запрет по риску → «ЗАПРЕТ» с обоснованием (без записи отклонения).
6. Критическое влияние на изделие → уверенность ≤ medium, утверждение руководителя КБ/ГСПП.
7. Фиксация согласованного отклонения только после узла human_approve; проверка запрета
   записи без HITL (write_gate).

## Критерии успеха
Достигнуты блокирующие KPI (`kpi.yaml`), пройдены проверки T1–T11 (`tests/`),
замечания журнала закрыты или переведены в план доработки с согласия владельца процесса.
