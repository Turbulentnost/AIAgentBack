# Агент инженера КБ / ГСПП (`kb_engineer_agent`)

Ролевой ИИ-агент контура №3 «Закупка и выбор поставщика» (доп. контур №5). ТЗ: **ТЗ-АГТ-КБ-001**.
Реестр ролевых агентов — строка 19. Уровень автономности **У1** (У2 — уведомления/маршрутизация).

> Статус: **архитектура (скелет)**. Внешние обращения (1С:ERP, RAG, LLM, document-service,
> оркестратор) — мок-заглушки `app.platform_sdk`. Боевые подключения не выполнены (`TODO(integration)`).

## Назначение
Экспертный агент с узкой блокирующей функцией: техническая проверка соответствия закупаемой
позиции КД (Ф1), извлечение обязательных требований (Ф2), разбор данных аналога (Ф3),
сопоставление и оценка допустимости (Ф4), формирование проекта технического заключения —
разрешение или запрет — с условиями применения и требуемыми изменениями КД (Ф5).
Заключение утверждает человек; согласованное отклонение фиксируется ДО размещения заказа.

## Функционал
Функциональные блоки выведены из должности «Инженер КБ / ГСПП» (реестр, строка 19) и шагов
СТО-28-020 (версия 07), СТО-10-095. **Экспертный** агент с узкой, но **блокирующей** функцией:
включается на шаге 2.5 по триггеру «любая замена или аналог»; заключение обязательно ДО заказа.

| Блок | Функция | Содержание |
|---|---|---|
| **Ф1** | Поднятие и проверка актуальности КД | Гибридный поиск КД/ТД (вектор + полнотекст по обозначению/пункту/версии); статус: действующая / изменена / заменена / отменена. При неактуальной или ненайденной КД заключение **не выдаётся** |
| **Ф2** | Извлечение обязательных требований | Характеристики из КД, ТД, спецификации и применимых ГОСТ; разметка обязательная/справочная; `source_reference` на каждое требование |
| **Ф3** | Разбор данных аналога | Паспорт, сертификат, техническое описание поставщика (PDF/DOCX/XLSX/скан + OCR); нормализация единиц и условий измерения; перечень недостающих сведений |
| **Ф4** | Сопоставление и оценка допустимости | Таблица соответствия требование ↔ аналог; ограничения применения, совместимость, ресурс, условия эксплуатации; покрытие критериев; оценка риска для изделия и производства. При покрытии < 100% заключение **не выдаётся** |
| **Ф5** | Формирование технического заключения | Проект «РАЗРЕШЕНИЕ» (с обязательными условиями и требуемыми изменениями КД) или «ЗАПРЕТ» (с обоснованием по каждому несоответствию); фиксация согласованного отклонения после утверждения |

**Типы задач (task_type):** `analog_review` · `substitution_review` · `kd_deviation_review` · `spec_clarification`.

**За человеком:** утверждение технического заключения (инженер КБ/ГСПП; при критическом
влиянии — руководитель КБ/ГСПП); внесение изменений в КД/ТД (по процедуре КБ); выбор поставщика
и коммерческая оценка аналога (область менеджера по закупкам); физический входной контроль,
измерения и испытания — модель не подменяет физический осмотр.

## Граф (nodes/)
Единый предметный поток (task_type задаёт содержание, не топологию):

`validate_input` → [невалидно → `assess_confidence`] → `load_kd_rag` → `check_kd_actuality`
→ [КД не актуальна → `assess_confidence`] → `extract_requirements` → `load_analog_data`
→ [нет обязательных данных → `list_missing_data` → `assess_confidence`]
→ `compare_characteristics` → `check_applicability` → `assess_risk`
→ [покрытие < 100% или запрет → `draft_conclusion_deny` → `assess_confidence`]
→ `draft_conclusion_allow` → `human_approve` (HITL) → `write_deviation_approval`
→ `assess_confidence` → `emit_result`.

Ветвь «ЗАПРЕТ» идёт на `assess_confidence` напрямую — без записи отклонения.

## Ключевые правила
- При неактуальной/ненайденной КД заключение не выдаётся (`data_confidence = low` + review).
- При покрытии обязательных критериев < 100% заключение не выдаётся (перечень недостающих данных).
- При критическом влиянии на изделие уверенность ≤ medium; утверждение руководителя КБ/ГСПП.
- Запись отклонения (`erp.write_deviation_approval`) — только после узла `human_approve`
  (write_gate); до HITL вызов блокируется. Согласованное отклонение — ДО заказа (K6).
- Каждое утверждение заключения — со ссылкой на источник (документ, пункт, версия, дата) (K5).
