# Агент анализа Excel (Авион)

## Текущие шаги

1. **Роли файлов** — `shipment_schedule`, `production_schedule`, `detailed_production_schedule`, `stock`, `specification`, `other`.
   - `production_schedule` — обычный **помесячный** график («Наименования изделий» + Июль/Август…); **только он** идёт в расчёты потребности;
   - `detailed_production_schedule` — **детальный** график/отчёт (график выпуска по дням, план/факт, «План по недельно»); пока **только классификация**, в расчёты не используется;
   - `stock` — остатки материалов («Номенклатура» + «Остаток…»); гибрид «план сверху + остатки снизу» → `stock`;
   - при загрузке на UI: `POST …/classify-excel` (только роли, без полного анализа);
   - UI: чеклист обязательных ролей (`production_schedule`, `stock`, `shipment_schedule`) до анализа; «Анализировать» только после валидации; при старте — 3D-переворот к шагам;
   - при «Анализировать» роли определяются снова в полном пайплайне.
2. **Изделия из графика производства** — только файлы роли `production_schedule` (не детальный); таблица «Наименования изделий» + помесячные qty (`ScheduleProductPlan`).
3. **Сопоставление со спецификациями** (`data/aveon/`):
   - изделие графика → `Номенклатура` из `Сопоставление номенклатур.xlsx`;
   - номенклатура → лист в `Сокол Спецификация из 1с.xlsx`.
4. **Материалы спецификаций** — merge уникальных номенклатур с изделиями и qty.
5. **Цены и поставщики** из `Цены закупки за 2026_0833.xlsx` → поля `supplier` / `price`.
6. **Остатки** из файла роли `stock` → `stock` (пустой = 0).
7. **Потребность по месяцам**:
   - `demand[месяц] = Σ (план_изделия[месяц] × qty_из_спеки_изделия)`.
8. **Ожидаемое поступление по месяцам** из файла роли `shipment_schedule`:
   - несколько листов (изделия); qty стоят под колонками дат поставки;
   - для каждой номенклатуры qty по датам группируются в календарный месяц;
   - если номенклатура есть на нескольких листах — количества за месяц складываются;
   - в памяти: `MergedNomenclatureRow.monthly_receipts`;
   - в `result.xlsx` — колонки «Ожидаемое поступление …».
9. **Риски логистики (контрольные точки на сегодня)** из того же графика отгрузок:
   - колонки «Логистика до МСК» / «Логистика МСК-Ростов» вида `7-14` / `5-10` (короткая–длинная, к.д.);
   - `D` = дата в колонке «Примерная дата поставки в Москву»;
   - после МСК — **таможня 2 к.д.**, затем плечо МСК→Ростов;
   - стадии: загрузка → МСК → таможня → Ростов;
   - МСК/Ростов: попадание, если сегодня внутри окна `[короткая … длинная]`;
   - у позиции: `days_remaining` до крайней (длинной) даты, `risk_ratio` / `risk_level` (зелёный→красный);
   - загрузка/таможня — точечные дни;
   - в API: `logistics_risks.stages[]`.
10. **Прогнозируемый остаток** (колонки H/K/N/Q/T/W в `Header.xlsx`):
   - первый месяц: `остаток(E) + поступление − потребность`;
   - далее: `предыдущий_прогноз + поступление − потребность`;
   - в Excel пишутся формулы (как в эталоне обеспеченности);
   - условное форматирование: значение `< 0` → заливка `#F4CCCC`, шрифт `#9C0006`.
11. **result.xlsx** по `Header.xlsx` (данные с 5-й строки).

## Поток

1. Пользователь загружает Excel (график производства, остатки, график отгрузок) и нажимает «Анализировать».
2. `POST /api/v1/agents/document-analysis/analyze-excel`.
3. Backend: роли → изделия → спеки → материалы → цены → остатки → потребность → поступления → прогноз остатка → риски логистики → `result.xlsx`.
