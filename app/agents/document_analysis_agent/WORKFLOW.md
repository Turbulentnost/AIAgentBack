# Агент анализа Excel (Авион)

## Текущие шаги

1. **Роли файлов** — `shipment_schedule`, `production_schedule`, `detailed_production_schedule`, `stock`, `specification`, `other`.
   - `production_schedule` — **помесячный** график («Наименования изделий» + месяцы); идёт в помесячную потребность;
   - `detailed_production_schedule` — **детальный** график выпуска по дням («План по недельно» и аналоги); идёт в лист «обеспечение (Месяц)»;
   - `stock` — остатки материалов («Номенклатура» + «Остаток…»); гибрид «план сверху + остатки снизу» → `stock`;
   - при загрузке на UI: `POST …/classify-excel` (только роли, без полного анализа);
   - UI: чеклист обязательных ролей (`production_schedule`, `stock`, `shipment_schedule`) до анализа; «Анализировать» только после валидации; при старте — 3D-переворот к шагам;
   - при «Анализировать» роли определяются снова в полном пайплайне.
2. **Изделия из графика производства** — файлы роли `production_schedule`:
   - при **1** файле — стандартный режим;
   - при **>1** — сравнение версий (ячейка «Версия»); на UI остаются только **2 последние**; в анализе потребность считается по новой версии, при расхождении планов по месяцам формируется `график_производства_изменения.xlsx` (колонки «было»/«стало», красные ячейки) + уведомление с перечнем месяцев.
   - **новый формат (3 уровня шапки):** месяц → Заказ / Опытные образцы / Склад → План / Факт;
   - модель: `ScheduleProductPlan.monthly_qty[месяц][категория][план|факт]`;
   - **legacy:** одна qty на месяц → пишется в `заказ/план`;
   - при нескольких листах в книге приоритет у split-таблицы.
3. **Детальный график** — файлы роли `detailed_production_schedule`:
   - при **1** файле — стандартный режим;
   - при **>1** — сравнение версий (ячейка «Версия»); на UI остаются только **2 последние**; в анализе дневная потребность по новой версии, при расхождении планов по датам формируется `детальный_график_изменения.xlsx` (колонки «было»/«стало», красные ячейки) + уведомление с перечнем дат;
   - **формат отчёта** («Модель / изделие», стадии **П/ф / ОТК / Склад**, пары план/факт под датами):
     - в дневную потребность идут **только строки «П/ф»** (ОТК и Склад игнорируются);
     - колонки «Итог недели» / «План месяца» / «Нарастающий» / примечания / риски пропускаются;
     - диапазон вида `01.07.2026-17.07.2026` распределяется равномерно по дням диапазона;
     - **план** после извлечения заполняется на **все дни месяца** (пропуски → 0);
     - **факт** хранится только за дни/периоды, где в файле есть значение;
   - legacy: дневные колонки (`1…31` или даты), колонки «Итог» / «План» / «Отклонение» / «Остаток» пропускаются;
   - несколько блоков «Наименование» на листе (legacy);
   - выбор месяца: календарный месяц даты анализа → ближайший будущий лист → иначе первый с дневными колонками;
   - модель: `DetailedScheduleProductPlan` (`daily_qty` план, `daily_fact` факт) / `DetailedScheduleExtract`.
   - шаблон скачивания: `шаблон_детальный_график_производства.xlsx` в формате отчёта П/ф.
4. **Сопоставление со спецификациями** (`data/aveon/`):
   - изделие графика → `Номенклатура` из `Сопоставление номенклатур.xlsx`;
   - номенклатура → лист в `Сокол Спецификация из 1с.xlsx`.
5. **Материалы спецификаций** — merge уникальных номенклатур с изделиями и qty; единица измерения (`unit`) берётся из колонки «Ед. изм.» спеки (первое непустое значение по номенклатуре).
6. **Цены и поставщики** из `Цены закупки за 2026_0833.xlsx` → поля `supplier` / `price`.
   - в итоговой колонке «Поставщик» **не** пишем `ИТЦ ООО` и `Магакян Екатерина Ивановна ИП` (и близкие написания) — оставляем пусто; цена при этом может остаться.
7. **Остатки** из файла роли `stock` → `stock` (пустой = 0); тот же остаток на обоих листах result.
8. **Потребность по месяцам** (6 колонок на месяц):
   - `demand[месяц][кат][план|факт] = Σ (qty_график[месяц][кат][метрика] × qty_спеки)`;
   - категории: Заказ, Опытные образцы, Склад.
9. **Ожидаемое поступление по месяцам** — **одна колонка** на месяц из `shipment_schedule`:
   - qty под колонками дат поставки → сумма в календарный месяц;
   - разрезы Заказ/Склад графика производства на поступление не влияют.
10. **Риски логистики (контрольные точки на сегодня)** из того же графика отгрузок:
   - колонки «Логистика до МСК» / «Логистика МСК-Ростов» вида `7-14` / `5-10` (короткая–длинная, к.д.);
   - `D` = дата в колонке «Примерная дата поставки в Москву»;
   - после МСК — **таможня 2 к.д.**, затем плечо МСК→Ростов;
   - стадии: загрузка → МСК → таможня → Ростов;
   - в API: `logistics_risks.stages[]`.
11. **Прогнозируемый остаток по месяцам** — **одна колонка** на месяц:
   - вычитается только **сумма планов** (Заказ+Опытные+Склад); колонки Факт в прогноз не входят;
   - `forecast₀ = остаток(E) + поступление − Σ(планы)`;
   - далее: `предыдущий_прогноз + поступление − Σ(планы)`;
   - в Excel — формулы; CF `< 0` → `#F4CCCC` / `#9C0006`.
12. **Обеспечение по дням** (тот же алгоритм, ключи = ISO-даты выбранного месяца):
   - из **детального графика** (строки **П/ф**): `demand_plan[day]` и `demand_fact[day]` = Σ (qty_изделия[день] × spec_qty);
   - факт только за дни/периоды, где в отчёте есть значение факта;
   - на листе `2-произв. план (Месяц)` на каждый день 4 колонки: Потребность план / Потребность факт / Ожидаемое поступление / Прогноз;
   - прогноз вычитает **только план** (как на помесячном);
   - `receipt[day]` — qty из графика отгрузок с датой поставки = этот день;
   - если детального файла нет — лист всё равно создаётся (A–E заполнены, дни = 0).
13. **result.xlsx**:
   - фиксированные колонки A–G: номенклатура, изделия, поставщик, **ед. изм.**, цена, остаток, заказано;
   - лист `1-производственный план (мес.)` — на месяц: деталь Заказ/Опыт/Склад (outline «+») + сводка Потребность План/Факт + поступления по неделям (outline «+») + итог поступления + прогноз; свёрнуто по умолчанию; данные с 6-й строки; прогноз = остаток/`F` + поступление − Σ планов;
   - лист `2-произв. план (Месяц)` — имя по выбранному месяцу детального графика (напр. `2-произв. план (Июль)`), программная шапка по дням, freeze `A5`, прогноз от `F`.
   - лист **`3-произв. план по обеспеч.`** — точная копия выбранного листа детального графика (Отчёт); красятся только ячейки **плана П/ф** с датой ≥ сегодня:
     - зелёный — covered ≥ plan; жёлтый — частично; красный — 0 / нет спеки;
     - прошлые дни/периоды без заливки; у периодов, пересекающих «сегодня», учитываются только оставшиеся дни;
     - расчёт по дням со списанием остатка+поступлений (fair share), модуль `product_coverage.compute_daily_plan_coverage`;
   - лист **`4-обеспеченность по изделиям`** — изделия × месяцы: колонки «Обеспеченность» / «План»;
     - План = Σ(Заказ+Опытные+Склад)·План из графика производства;
     - Обеспеченность = сколько изделий можно собрать из остатка на начало месяца + поступлений месяца (BOM из спеки);
     - под каждым изделием — outline («+» слева): все номенклатуры из спеки; в месяце План = план изделия × qty, Обеспеченность = остаток + поступления (свёрнуто по умолчанию);
     - изделие считается собираемым только если **все** позиции спеки покрыты остатком+приходом (с учётом qty); нет в остатках/отгрузках → доступно 0 → блокирует сборку;
     - поступления до первого месяца горизонта входят в opening;
     - общие комплектующие: пропорциональный масштаб α по планам; изделие с нулевым эксклюзивным материалом не обнуляет остальные; затем добор по 1 шт сверху вниз;
     - closing месяца = пул после списания под covered → opening следующего месяца;
     - модуль: `product_coverage.py`.
   - лист **`план заказов`** — номенклатуры (как на помесячном) × месяцы: «Дата заказа» / «Количество, шт»;
     - дата = 1-е число месяца − (long МСК + 2 таможня + long Ростов) из графика отгрузок; нет в графике → 21 день;
     - количество = скользящий дефицит: `max(0, плановая потребность − opening − поступления месяца)`; заказ считается прибывшим к 1-му и закрывает дыру на текущий/следующие месяцы;
     - в Excel количество — **формулы** на остаток (F), потребность-план и ожидаемое поступление с листа `1-производственный план (мес.)` (+ qty прошлых месяцев этого листа);
     - **сценарий:** смотрите qty в «план заказов» → вставляете в редактируемый итог «Ожидаемое поступление» на помесячном → qty заказа пересчитывается (обычно в 0, если дыра закрыта); недели в outline — справочно, на итог не влияют;
     - потребность = Σ(план изделий × qty спеки) из `monthly_demand`;
     - модуль: `order_plan.py`.
14. **Дашборд контрольных точек** — после анализа сохраняется на сервере (`data/aveon/dashboard_snapshots/<user>.json`); `GET …/dashboard-latest` отдаёт последний снимок при открытии страницы; новый анализ перезаписывает снимок. Этапы анализа и сменное задание **не** восстанавливаются при повторном заходе — только после нового анализа.
15. **сменное_задание_закупки.xlsx** (отдельный файл, скачивание по кнопке в Сводке UI):
   - лист `Как работать` — дата, счётчики срочно/сегодня/на неделе, оценка времени;
   - лист `Задания` — единый список дел: приоритет, проблема, что сделать, время на решение, номенклатура, поставщик, количество, срок (логистика high/critical + дефицит на неделе).

## Поток

1. Пользователь загружает Excel (график производства, опционально детальный, остатки, график отгрузок) и нажимает «Анализировать».
2. `POST /api/v1/agents/document-analysis/analyze-excel`.
3. Backend: роли → помесячные изделия (split/legacy) → детальный график → спеки → материалы → цены → остатки → потребность (кат×план/факт) / поступления / прогноз(Σ планов) → дневные расчёты → риски → обеспеченность изделий → план заказов → `result.xlsx` + `сменное_задание_закупки.xlsx`; сохранить dashboard snapshot.
