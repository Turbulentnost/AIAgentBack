# План: лист «обеспеченность» (изделие × месяц)

## 1. Цель

В `result.xlsx` добавить **третий лист** `обеспеченность`:

| Изделие (как в графике производства) | … для каждого месяца: **Обеспеченность** | **План** … |

- **План** — суммарный план выпуска изделия за месяц из графика производства  
  (`заказ.план + опытные.план + склад.план`).
- **Обеспеченность** — сколько изделий **можно собрать** в этом месяце из доступных материалов  
  (остаток на начало месяца + поступления месяца), с учётом спецификаций и справедливого распределения общих комплектующих.

Сейчас агент считает обеспеченность **материалов** (`помесячное обеспечение`).  
Новый лист — обеспеченность **готовых изделий**.

---

## 2. Входы (уже есть в пайплайне)

| Источник | Что берём |
|----------|-----------|
| `График производства.xlsx` → `ScheduleProductPlan` | Порядок изделий сверху вниз; `monthly_qty[месяц][кат][план]` |
| `Сокол Спецификация из 1с.xlsx` + сопоставление | BOM: `MergedNomenclatureRow.by_product[изделие]` = qty на 1 изделие |
| `С остатками.xlsx` → `row.stock` | Остаток на дату анализа = opening месяца 0 |
| `ГРАФИК ОТГРУЗОК…` → `row.monthly_receipts` | Поступления в календарный месяц |
| `помесячное обеспечение` (логика forecast) | Opening следующих месяцев = closing после расхода предыдущего |

Строки `ИТОГО:` в графике уже отфильтрованы при парсинге — в лист не попадают.

Пример из графика (`Июнь выпуск Доп`):

- Июль: «СОКОЛ» И — план 6800 (заказ) + 40000 (склад) = **46800** суммарно план  
- Июль: «СОКОЛ» Т — 3000 + 40000 = **43000**  
- Общие материалы (Talon Pro, XT60, провода…) делятся между изделиями → нельзя «обнулить» нижние строки.

## 3. Модель данных (новые структуры)

Файл (новый): `product_coverage.py` рядом с `excel_service.py`.

```text
MonthMaterialPool:
  month: str
  items: dict[norm_name → MaterialMonthState]

MaterialMonthState:
  nomenclature: str
  opening: float          # остаток перед месяцем
  receipts: float         # поступления за месяц
  available: float        # opening + receipts (пул для сборки)
  plan_demand: float      # Σ плановой потребности из monthly_demand (для справки/отладки)
  consumed: float         # сколько списано на сборку в этом месяце
  closing: float          # available - consumed → opening следующего месяца

ProductBom:
  product: str
  materials: dict[norm_name → qty_per_unit]   # из by_product / SpecMaterialItem
  matched: bool

ProductMonthCoverage:
  product: str
  month: str
  plan: float             # Σ план по категориям
  covered: float          # сколько можно собрать (целое или floor)
  cover_ratio: float      # covered / plan (если plan>0)
  limiting_materials: list[str]  # узкие места (для лога / опц. скрытого листа)

ProductCoverageResult:
  months: list[str]
  products_in_order: list[str]   # порядок строк графика
  boms: dict[product → ProductBom]
  pools: dict[month → MonthMaterialPool]
  cells: dict[(product, month) → ProductMonthCoverage]
```

## 4. Алгоритм расчёта (ядро)

### 4.1. Подготовка

1. `months` = порядок месяцев из `ScheduleProductPlan` (как на помесячном листе).
2. `products_in_order` = изделия графика в порядке появления (без ИТОГО).
3. Для каждого изделия: BOM из `by_product` по всем `MergedNomenclatureRow`  
   (если спека не сматчилась → `matched=False`, `covered=0` при `plan>0`).
4. `plan[p, m] = Σ_кат schedule[p].monthly_qty[m][кат][план]`.

### 4.2. Пул материалов на месяц

Для месяца `m` и материала `n`:

- **m = первый месяц:** `opening = row.stock` (как колонка «Остаток»).
- **иначе:** `opening = closing` предыдущего месяца из этой же модели покрытия  
  (не из Excel-формул прогноза — единый источник правды в Python).
- `receipts = row.monthly_receipts.get(m, 0)`.
- `available = max(0, opening) + max(0, receipts)`.

> Нюанс: прогноз на «помесячном» листе списывает **всю** плановую потребность материалов.  
> Лист «обеспеченность» списывает только материалы под **фактически покрытый** выпуск (`covered`).  
> Closing для следующего месяца = `available − consumed_by_covered`.  
> Это согласовано с смыслом «сколько реально соберём», а не «сколько нужно по полному плану».

Альтернатива (зафиксировать в приёмке): closing как у forecast (`opening + receipts − полная plan demand`).  
**Рекомендация MVP:** closing от **covered** (реалистичный остаток после сборки).

### 4.3. Справедливая обеспеченность + приоритет сверху вниз

Проблема: жадный top-down даст «верхним» 100%, нижним 0% при общем дефиците.  
Нужно соотношение планов.

**Шаг A — пропорциональный масштаб α ∈ [0, 1]**

Максимизировать α такой, что для каждого материала `n`:

```
Σ_p (α · plan[p,m] · bom[n,p]) ≤ available[n]
```

только по изделиям с `plan[p,m] > 0` и валидным BOM.

Решение: для каждого материала

```
α_n = available[n] / Σ_p (plan[p,m] · bom[n,p])   # если знаменатель > 0
α = min(1, min α_n по всем n)
```

Тогда черновое покрытие: `raw[p] = α · plan[p,m]`.

**Шаг B — округление вниз + добор по приоритету строк**

1. `covered[p] = floor(raw[p])` (для штучных BOM; для дробных qty в BOM оставляем float с 3 знаками или floor по узкому месту).
2. Остаток «квот» / материалов после floor — **добор по 1 изделию** сверху вниз по `products_in_order`, пока `covered[p] < plan[p,m]` и хватает BOM.
3. Это сохраняет пропорции и отдаёт «остатки» приоритету верхних строк.

**Шаг C — списание пула**

```
consumed[n] = Σ_p covered[p] · bom[n,p]
closing[n] = available[n] − consumed[n]
```

Перейти к следующему месяцу.

### 4.4. Краевые случаи

| Кейс | Поведение |
|------|-----------|
| `plan = 0` | `covered = 0`, ячейки 0 / пусто |
| Нет спеки | `covered = 0`, в лог `unmatched_spec` |
| BOM qty = 0 / пусто | материал не ограничивает |
| Материал только у одного изделия | α и добор обычные |
| `available = 0`, план > 0 | `covered = 0` |
| Дробные единицы (м, кг) | не floor по изделию из‑за провода: лимит = `available/bom` float; `covered = floor(min лимитов)` |
| Несколько листов спеки / одно изделие | уже сведено в `by_product` |
| Изделие в графике, но не в спеках aveon | 0 + статус |
| Поступления после «логической» даты сборки | MVP: весь месяц доступен сразу (как сейчас в forecast) |

## 5. Формат листа Excel

Имя: **`обеспеченность`** (константа `_SHEET_PRODUCT_COVERAGE`).

Шапка (3 строки, стиль как у помесячного):

```
R1: Обеспеченность плана производства изделиями (сборка из материалов)
R2: План = Σ(Заказ+Опытные+Склад)·План из графика; Обеспеченность = сколько изделий
    можно собрать из остатка на начало месяца + поступлений месяца; общие комплектующие
    делятся пропорционально планам, остаток квот — сверху вниз по строкам графика
R3: Изделие | Июль |        | Август | …
R4:         | Обеспеченность | План | Обеспеченность | План | …
```

- Col A: наименование изделия (порядок = график).  
- На месяц: 2 колонки.  
- CF: `Обеспеченность < План` → мягкий warning fill (не красный дефицит материалов).  
- Freeze `B5`.  
- Опционально (фаза 2): скрытый/второй лист `обеспеченность (материалы)` с пулом opening/receipts/consumed.

Позиция в книге:

1. `помесячное обеспечение`  
2. `обеспечение (Месяц)`  
3. **`обеспеченность`** ← новый

## 7. Псевдокод ядра

```python
def compute_product_coverage(plans, merged, months):
    order = [p.product for p in plans]
    bom = build_bom_from_merged(merged, order)
    stock0 = {norm(r.nomenclature): r.stock or 0 for r in merged}
    receipts = {norm(r.nomenclature): r.monthly_receipts for r in merged}
    opening = dict(stock0)
    cells = {}

    for month in months:
        available = {
            n: max(0.0, opening.get(n, 0.0)) + max(0.0, receipts.get(n, {}).get(month, 0.0))
            for n in all_materials(bom)
        }
        plan_m = {p: plan_total(plans, p, month) for p in order}
        active = [p for p in order if plan_m[p] > 0 and bom[p].matched]

        # A: alpha
        alpha = 1.0
        for n, avail in available.items():
            need = sum(plan_m[p] * bom[p].materials.get(n, 0.0) for p in active)
            if need > 0:
                alpha = min(alpha, avail / need)

        covered = {p: math.floor(alpha * plan_m[p]) for p in active}

        # B: top-down +1
        def can_build(p, pool):
            return all(pool.get(n, 0) + 1e-9 >= q for n, q in bom[p].materials.items() if q)

        def consume(p, pool, k=1):
            for n, q in bom[p].materials.items():
                pool[n] = pool.get(n, 0) - k * q

        pool = dict(available)
        for p in active:
            consume(p, pool, covered[p])

        changed = True
        while changed:
            changed = False
            for p in active:  # сверху вниз
                if covered[p] + 1 <= plan_m[p] and can_build(p, pool):
                    covered[p] += 1
                    consume(p, pool, 1)
                    changed = True

        for p in order:
            cells[(p, month)] = ProductMonthCoverage(
                plan=plan_m[p],
                covered=covered.get(p, 0.0),
                ...
            )
        opening = {n: max(0.0, pool.get(n, 0.0)) for n in pool}  # closing

    return ProductCoverageResult(...)
```

## 8. Риски и нюансы

1. **Общие KIT** (Talon Pro у И/Т/ИС) — главный смысл пропорционального α.  
2. **Расхождение имён** график ↔ спека — уже через «Сопоставление номенклатур»; ошибки → covered=0.  
3. **Склад 40000** в графике раздувает plan — обеспеченность может быть << plan; это ожидаемо.  
4. **Двойной смысл «обеспеченность»** в UI (материалы vs изделия) — в подзаголовке листа явно писать «сборка изделий».  
5. **Производительность** — O(months × products × materials); для ~20 изделий × ~400 номенклатур × 6 месяцев — мгновенно.  
6. **Согласование с forecast** — числа на двух листах не обязаны совпадать 1:1 (разные модели списания); описать в WORKFLOW.  
7. **Факт** графика в покрытие **не** входит (как и в прогноз материалов).
