# Агент заместителя начальника ОМТО (`omto_deputy_agent`)

Ролевой ИИ-агент контура №3 «Закупка и выбор поставщика». ТЗ: **ТЗ-АГТ-ОМТО-ЗАМ-001**.
Реестр ролевых агентов — строка 16. Уровень автономности **У1** (У2 — уведомления/маршрутизация).
Нормативная база: **СТО-28-020 «Закупки» (версия 07)**.

> Статус: **архитектура (скелет)**. Внешние обращения (1С:ERP, RAG, LLM, оркестратор)
> — мок-заглушки `app.platform_sdk`. Боевые подключения не выполнены (`TODO(integration)`).

## Назначение
Диспетчерский агент: распределение закупочных позиций между менеджерами и контроль очереди
нераспределённых позиций (шаг 2.1 СТО-28-020). Ведёт очередь (Ф1) → контролирует дубли (Ф2)
→ классифицирует позицию и подбирает специализацию (Ф3) → балансирует загрузку (Ф4) →
формирует проект назначения ответственного менеджера с обоснованием и эскалирует
нераспределённые позиции (Ф5). Агент формирует ТОЛЬКО проект; утверждение и запись —
после подтверждения начальником ОМТО.

## ⚠️ Открытая коллизия D01
СТО-28-020 указывает заместителя начальника ОМТО как создателя заказа поставщику, тогда как
СТО-06-010 допускает создание заказа главным диспетчером. **До закрытия решения D01 системного
ТЗ агент формирует ТОЛЬКО проект назначения и НЕ создаёт заказ поставщику.** Записывается
исключительно реквизит «Ответственный» (после HITL). Отражено в `graph.py`, `nodes/drafts.py`
(докстринги `draft_assignment`, `writeback_1c`, `escalate_to_head`) и `agent.yaml`.

## Функционал
Функциональные блоки выведены из должности «Заместитель начальника ОМТО» (реестр, строка 16)
и шага 2.1 СТО-28-020 (версия 07). Роль — **диспетчерская**: распределение закупочных позиций
между менеджерами и контроль очереди. Агент формирует ТОЛЬКО проект назначения.

| Блок | Функция | Содержание |
|---|---|---|
| **Ф1** | Ведение очереди нераспределённых позиций | Считывание позиций с пустым реквизитом «Ответственный»; обогащение (номенклатурная группа, дата потребности, ЦФО, приоритет); расчёт времени в очереди vs допустимый срок |
| **Ф2** | Контроль дублей | Поиск открытых заказов и ранее сформированных кейсов на ту же потребность; при дубле — связывание с существующим кейсом, новое назначение не создаётся |
| **Ф3** | Классификация и подбор специализации | Номенклатурная группа по справочнику арендатора, срочность/критичность; сопоставление с матрицей специализаций менеджеров |
| **Ф4** | Балансировка загрузки | Учёт текущей загрузки и доступности (отпуск/больничный/командировка); минимизация отклонения от средней загрузки (≤ 20%); предложение по перераспределению при перекосе |
| **Ф5** | Проект назначения и эскалация | Проект назначения с объяснимым обоснованием (специализация, загрузка, срок, приоритет); при отсутствии кандидата/просрочке — проект эскалации начальнику ОМТО |

**Типы задач (task_type):** `assign_positions` · `queue_review` · `rebalance_workload`.

**За человеком:** утверждение назначения (начальник ОМТО); создание/проведение заказа
поставщику (см. коллизию D01); любые действия по существу закупки (поиск, RFQ, договор, счёт);
изменение штатной структуры, специализаций и лимитов (задаётся конфигурацией арендатора).

## Граф (nodes/)
`validate_input` → диспетчеризация по `task_type`:
- `assign_positions` → `load_queue_1c` → `check_duplicates`
  - дубль → `link_to_existing_case` → `assess_confidence`
  - иначе → `load_managers_profile` → `classify_position` → `match_specialization`
    - нет кандидата/специализации → `escalate_to_head` → `assess_confidence`
    - иначе → `balance_workload` → `draft_assignment` → `human_confirm` (HITL) →
      `writeback_1c` → `assess_confidence`
- `queue_review` → `load_queue_1c` → `check_duplicates` → (дубль → `link_to_existing_case`) →
  `assess_confidence`
- `rebalance_workload` → `load_managers_profile` → `balance_workload` → `draft_assignment` →
  `human_confirm` (HITL) → `writeback_1c` → `assess_confidence`

Все ветви сходятся: `assess_confidence` → `emit_result` → END.

## Ключевые ограничения
- Заказ поставщику не создаётся (коллизия D01); формируется только проект назначения.
- Запись в 1С (реквизит «Ответственный») — только по белому списку и после точки HITL (`write_gate`).
- Каждое назначение — со ссылкой на источник и объяснимым обоснованием (K6).
- Дубли потребности в закупку не передаются (K5, блокирующий); позиций без ответственного
  сверх допустимого срока — 0 (K2, блокирующий).
