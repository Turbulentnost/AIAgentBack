# Шаблон заполнения: «Входящая корреспонденция (создание)»

> Форма 1С: **Документ → Входящая корреспонденция → Создание**  
> OData-сущность: `Document_ТД_ВходящаяКорреспонденция`  
> Автозаполнение: узел 7 (`n7_create_erp_task`) → `odata_incoming_mapper.build_incoming_document_payload`  
> Дата шаблона: 2026-07-07

**Условные обозначения**

| Маркер | Значение |
|--------|----------|
| 🔴 **ОБЯЗАТЕЛЬНО** | Поле с красной рамкой на форме 1С; без него карточку нельзя записать |
| ⚪ | Необязательное на форме; агент может заполнить или оставить пустым |
| ✅ | Заполняется агентом автоматически (при корректной конфигурации) |
| ⚠️ | Частично / с пробелами — см. примечания |
| ❌ | Агент **не** заполняет — только вручную в 1С или через `ODATA_INCOMING_EXTRA_FIELDS` |

## Цепочка автозаполнения (кратко)

```
IMAP (узел 1)          → EmailMessage
       ↓
Спам / контент (2–4)   → combined_text, вложения
       ↓
Маршрутизация (узел 5) → RoutingResult + XML document
       │                  routing/engine.py: organization, direction, partner (RAG)
       │                  xml_builder.py: <document>…</document>
       ↓
Обзор (узел 6)         → summary_ru
       ↓
1С OData (узел 7)      → build_incoming_document_payload()
                         → POST Document_ТД_ВходящаяКорреспонденция
```

## XML document (ТЗ §12) — теги и соответствие полям 1С

| XML-тег | Поле 1С | Как формируется |
|---------|---------|-----------------|
| `<organization>` | Организация | `routing.detect_organization()`; по умолчанию `НП` |
| `<theme>` | Тема | LLM `xml_theme` или заглушка из темы письма |
| `<направление>` | *(Направление)* | `detect_direction(org, rule.direction)`; по умолчанию `КС` |
| `<claim>` | Претензия | `contains_claim_marker(subject + body)` |
| `<partner>` | Партнер, Плательщик-направление | RAG `contractors` по email отправителя; если нет — `-` |
| `<services><service><name>` | Подразделение (код), Кому | Код `00-XXXXXX` из правил маршрутизации |
| `<service><title>` | Подразделение (название) | `routing.department_name` |
| `<email_sender>` | Email отправителя | `email.sender_email` |
| `<email_recipient>` | Email получателя | Ящик / `routing_recipient` |
| `<mail_datetime>` | Дата, Дата исх. | `email.received_at` |
| `<process>` | — | `исполнение` (служебное, не OData) |

Пример XML:

```xml
<document>
  <organization>НП</organization>
  <theme>Запрос акта сверки - акт сверки</theme>
  <направление>КС</направление>
  <claim>false</claim>
  <partner>ООО «Газпром трансгаз»</partner>
  <services>
    <service>
      <name>00-000076</name>
      <title>Отдел договорной работы</title>
      <process>исполнение</process>
      <reasoning>Re: Договор поставки</reasoning>
    </service>
  </services>
  <email_sender>client@example.ru</email_sender>
  <email_recipient>info@turbo-don.ru</email_recipient>
  <mail_datetime>2026-07-03 10:00:00</mail_datetime>
  <process>исполнение</process>
</document>
```

## Примечания для оператора

1. **Проверяйте 🔴 поля перед подтверждением** — особенно «Партнер» и «Плательщик-направление», если отправитель не найден в справочнике контрагентов.
2. **Подразделение** на форме — человекочитаемое имя; в поле «Кому» — код `00-XXXXXX`. Оба должны соответствовать одному отделу.
3. **Тема** в 1С часто длиннее темы письма: агент добавляет ключевую фразу (`описание - категория`).
4. **Содержание** — краткий обзор письма (3–5 предложений), не полный текст.
5. **Комментарий** в OData содержит служебную информацию (уверенность, ключевые слова, полный XML) — в UI 1С может отображаться отдельно.
6. При **низкой уверенности** (`AGENT_MODE=review`) документ не создаётся автоматически — оператор правит XML/HITL и запускает повтор.

## Примечания для разработчика

| Тема | Детали |
|------|--------|
| OpenType-поля | `Автор`, `Подразделение` — пользовательские реквизиты карточки (не в `$metadata`, но принимаются OData) |
| Пустые GUID | `Организация_Key` / ключи подразделений не отправляются, если GUID пустой или `00000000-…` |
| Партнер `-` | В XML допустимо `-`; в OData поле **не** попадает (`partner == "-"` → пусто) |
| Дублирование Содержание | `ai_task_theme` и `content` оба маппятся на `Содержание`; фактически пишется `summary_ru` |
| Режим dry_run | `AGENT_MODE=dry_run` — XML формируется, POST в 1С не выполняется |
| HITL | `rebuild_xml_document_from_row` пересобирает XML после правки оператором |

## Пробелы автозаполнения (обязательные поля)

| 🔴 Поле | Статус | Причина / что сделать |
|---------|--------|------------------------|
| **Организация** | ⚠️ Частично | Нужен `ODATA_ORGANIZATION_KEYS` с GUID для кода из XML (`НП`, `АЛ`, …). Без JSON ключ не уходит в POST → 1С может отклонить запись. |
| **Тема** | ✅ | Всегда есть fallback: `email.subject` или «Без темы». |
| **Подразделение** | ⚠️ Частично | Имя — из routing; GUID ссылки — только при `ODATA_DEPARTMENT_KEYS`. Без GUID имя может быть недостаточно для формы. |
| **Партнер** | ⚠️ Частично | Только если отправитель найден в RAG (`Catalog_КонтрагентыForMail`). Неизвестный отправитель → XML `<partner>-</partner>` → OData **пусто** → 🔴 не заполнено. |
| **Плательщик-направление** | ⚠️ Частично | Копируется из партнёра; та же проблема при отсутствии контрагента. Отдельного извлечения плательщика из текста письма нет. |

### Необязательные поля без автозаполнения

| Поле | Статус | Рекомендация |
|------|--------|--------------|
| Номер исх. (`НомерИсходящий`) | ❌ | Парсинг из темы/тела или ручной ввод |
| Контрагент (`Контрагент_Key`) | ❌ | Отдельная привязка к справочнику 1С (≠ строковый «Партнер») |
| Гриф доступа (`ГрифДоступа_Key`) | ❌ | Политика безопасности / `ODATA_INCOMING_EXTRA_FIELDS` |
| Дата исх. | ⚠️ | Сейчас = дата входящего письма, не дата исходящего документа контрагента |
